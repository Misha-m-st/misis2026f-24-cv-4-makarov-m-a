# Телефонный test set: SAM 3 и геометрия листа

Подготовщик — простой Python-скрипт через `uv run` в общей корневой `.venv`.
Извлечение, SAM-адаптер и геометрия находятся в этом подпроекте и не импортируют `document_vos`.
Обучение и архитектура Cutie не меняются.

Используется **SAM 3 Image**, независимо на кадрах 0, 10, 20, 30…
[Релиз SAM 3.1](https://github.com/facebookresearch/sam3/blob/main/RELEASE_SAM3p1.md) добавляет
Object Multiplex и улучшения видеотрекинга нескольких объектов. Здесь видео обрабатывает Cutie,
поэтому видеопредиктор SAM не создаётся. Источник весов — [facebook/sam3](https://huggingface.co/facebook/sam3).

## Совместимость и локальные веса

Код SAM закреплён в общем `uv.lock` на `0570b3a5be9c4e694f23d85232fb55f4a6f1f7fc`.

```bash
uv sync --extra phone-testset --extra dev
uv run --extra phone-testset tools/phone_testset/prepare.py --check-compatibility
```

Фактический импорт Image API в общей `.venv` — **PASS**. Torch 2.14.1+cu130 и torchvision
0.29.1+cu130 сохранены. Из-за требования upstream `numpy<2` согласованы NumPy 1.26.4,
OpenCV 4.11.0 и SciPy 1.17.1. Для upstream `pkg_resources` закреплён setuptools 80.9.0.
[Сохранённая проверка](../../docs/PHONE_TESTSET_COMPATIBILITY.json).
Реальный CUDA forward проверен на первых кадрах девяти локальных телефонных видео:
восемь видимых масок приняты, один кадр отклонён из-за неоднозначных экземпляров.
После исправления геометрии пять начальных масок проходят её проверки; три отклоняются.
[Evidence smoke](../../docs/PHONE_TESTSET_REAL_SMOKE.json).
Полная подготовка после последующих исправлений выбора экземпляров и геометрии проверена
на этих девяти видео в `cutie-test-v3`: **NO_ELIGIBLE_VIDEOS**, 20 масок приняты,
каждая последовательность отклонена при следующем непригодном размечаемом кадре.
[Результат полной подготовки](../../docs/PHONE_TESTSET_V3_RESULT.json).
Оценка качества Cutie — **NOT_RUN**: нет допущенных последовательностей.
`--check-compatibility` проверяет только импорт и сам не выполняет forward.

Веса не скачиваются автоматически. Получите доступ и локальный checkpoint SAM 3 самостоятельно
через официальную страницу, затем передайте `--weights`. Словарь токенизатора включён в пакет.
Адаптер использует `load_from_HF=False` и строго загружает все используемые image detector weights
из локального файла. Из официального checkpoint исключается только неиспользуемый интерактивный
feature neck `backbone.vision_backbone.sam2_convs.*`, отсутствующий при выключенной интерактивности.
Все прочие лишние, отсутствующие или несовместимые параметры остаются ошибками.
Неполный checkpoint отклоняется. Отдельного Python-окружения и процесса модели нет.

FFmpeg и ffprobe устанавливаются отдельно, например `sudo apt install ffmpeg`, либо задаются
через `--ffmpeg`/`--ffprobe`. Тесты используют временные статические FFmpeg/ffprobe 7.0.2.

## Геометрическая гипотеза

Цель — **полный контур плоского прямоугольного листа в перспективе**, включая закрытые части.
Видимая маска SAM сохраняется отдельно.

`geometry.py` строит выпуклую оболочку внешних контуров маски, выделяет длинные сегменты,
уточняет прямые по пикселям видимой границы, перебирает четыре стороны и пересекает их.
Упрощение оболочки использует тот же допуск 2.5 пикселя, что и подгонка прямых; метод
`supported-boundary-lines/v4-clipped` записывается в fingerprint подготовки и evidence масок.
Ограничение числа кандидатов применяется к длинным поддержанным сторонам, а не к мелким
вершинам оболочки. Гипотезы с совпадающими в пределах допуска границами внутри изображения
считаются одной гипотезой; различимые гипотезы остаются причиной отказа при близких оценках.
Кандидат проходит проверки выпуклости, углов, поддержки сторон, охвата видимой области,
расширения площади и неоднозначности. Принятый четырёхугольник растеризуется в маску 0/1.
Параллельность и прямые углы в изображении не навязываются.

Это позволяет заполнить отверстие от руки или восстановить закрытый угол/участок стороны,
когда сохранились достаточные участки всех четырёх сторон. При недостаточной опоре — отказ с причиной.

Пороги: сегмент ≥10% диагонали; поддержка каждой стороны ≥55%; охват видимой маски ≥99.5%;
площадь результата / видимая площадь ≤1.65; видимая площадь ≥0.5% кадра;
углы 20°–160°; расстояние до прямой ≤2.5 пикселя.
Это эвристические gates, ещё не откалиброванные на настоящих телефонных видео.

Касание границы изображения и выход углов за кадр допустимы, как требует `main_plan.md`.
Пиксели искусственной границы кадра не считаются стороной документа. Поддержка физических
сторон измеряется только на участках внутри изображения. Полные координаты углов сохраняются,
а маска строится через пересечение четырёхугольника с изображением, не через прижимание углов.
`clipped_polygon` может иметь пять и более вершин; `out_of_frame` записан в evidence.
Полностью невидимая сторона сама по себе не получает выдуманной опоры.

[Проверка на сохранённых реальных масках](../../docs/PHONE_TESTSET_CLIPPING_SMOKE.json):
29 из 33 размечаемых кадров одного полного видео проходят геометрию, включая кадры
90–150 и 310–320 с выходящими за кадр углами; четыре кадра остаются неоднозначными.
Это повторная обработка исходных SAM outputs, а не повторный forward или оценка качества.
Исторический результат `cutie-test-v3` выше получен до исправления пересечения с кадром.

При полном уходе листа пустое пересечение восстановленного контура с изображением является
корректной маской отсутствия. Однако отсутствие детекции SAM не доказывает уход листа:
автоматически превращать такой результат или ошибку модели в нулевую GT-маску нельзя.
Текущий подготовщик не подтверждает отсутствие объекта по движению и продолжает отмечать
невосстановленный контур как непригодную автоматическую разметку. Начальная маска непустая.

**Контур под окклюзией непосредственно не наблюдается.** Согласованные линии не доказывают
правильность восстановления. Полностью скрытую сторону или видимую область, похожую на меньший лист,
может быть невозможно восстановить из одной маски. Временная гомография не используется.
Физически изогнутые страницы текущей геометрической моделью не поддерживаются.

## Подготовка

```bash
uv run --extra phone-testset tools/phone_testset/prepare.py \
  --videos /path/to/phone-a.mp4 /path/to/phone-b.mov \
  --weights /path/to/local/sam3.pt \
  --output tools/phone_testset/data/my-test \
  --prompt "sheet of paper" \
  --max-masks 1 \
  --step 10
```

Шаг настраивается через `--step`. Порог SAM `--min-score` по умолчанию 0.5.
`--max-masks` задаёт положительное максимальное число масок, по умолчанию **1**.
Выбор `largest-area/nonoverlapping-v2` сначала отсеивает маски ниже порога confidence,
затем сортирует оставшиеся по площади в пикселях. Маска удаляется целиком, если имеет хотя бы
один общий пиксель с любой более крупной маской, прошедшей порог confidence; это действует
и при большом `--max-masks`. Затем к непересекающимся маскам применяется лимит количества.
Маски не обрезаются и не объединяются. При равной площади выше ставится confidence,
затем исходный индекс; из пересекающихся равных масок остаётся первая по этому порядку.
Близкий confidence разных масок
сам по себе не является ошибкой. Площадь, исходные индексы и число кандидатов записываются в evidence.
Подготовка для Cutie размечает один лист: геометрия применяется к самой большой маске.
Если её контур восстановить невозможно, ошибка сохраняется; меньший объект не подставляется.
Лимит больше 1 позволяет показать несколько крупнейших масок в диагностическом просмотре.
Параметр `--instance-margin` оставлен для старых команд, но при выборе по площади не используется.
Лимит и способ выбора входят в fingerprint: для новых настроек нужен новый output либо явный `--recreate`.
Геометрические параметры:
`--min-side-support`, `--max-area-ratio`; остальные задаёт `GeometryOptions` в Python API.

Все декодируемые кадры извлекаются без изменения FPS/разрешения, с FFmpeg autorotation и
`-fps_mode passthrough`. Время берётся из целочисленных source PTS и `time_base` ffprobe,
не из номинального FPS. PTS, поворот и размеры сохранены в provenance.
Ошибочные/отсутствующие/не возрастающие timestamps и несовпадения количества/размеров кадров отклоняются.
Внутреннее преобразование входа SAM не меняет сохранённые кадры; маски возвращаются в исходном размере.

Все прошедшие проверки маски приняты автоматически, без редактора и подтверждений.
Ошибка SAM или геометрии на первом кадре делает видео непригодным: для инициализации
Cutie нужна корректная непустая маска. На последующих размечаемых кадрах ошибка сохраняется
в `annotations.jsonl` и `provenance.phone_testset.annotation_failures`, кадр остаётся без GT,
а подготовка продолжается. Все кадры допущенного видео передаются Cutie в исходном порядке.
Метрики вычисляются только на кадрах с принятой разметкой после инициализации.
Ошибки не заменяются видимыми или нулевыми масками. Частичные кадры и полученные маски сохраняются.
`annotation_coverage` содержит число запланированных, принятых и неудачных разметок после
первого кадра и долю покрытия. Снимок запуска сохраняет эти сведения; отчёт оценки показывает
покрытие и причины доступны в JSON. Если принятой разметки после первого кадра совсем нет,
видео участвует в инференсе, но для него нельзя получить численные метрики.
Политика `initial-required/skip-later-v1` входит в fingerprint подготовки: прежние наборы
с отказом всего видео автоматически не изменяются, нужен новый `--output` либо явный `--recreate`.

Политика проверена реальной подготовкой `video_20261011_005139.mp4` в
`tools/phone_testset/data/cutie-test-sparse-005139`: видео допущено, сохранены все 337 кадров,
маски имеются на индексах 0, 10, 20, 320 и 330. Остальные 29 запланированных разметок
не приняты, включая кадр 60. Покрытие оценочной разметкой после инициализации — 4/33 (12.1%).
Это проверка подготовки и отбора папки, не запуск Cutie и не оценка качества сегментации.
Evidence — `docs/PHONE_TESTSET_SPARSE_ANNOTATION_SMOKE.json`; 54 теста протокола прошли.

```text
my-test/
  preparation.json              # параметры и хеши видео/весов
  preparation_result.json
  manifest.jsonl                # все видео и причины непригодности
  annotations.jsonl             # confidence, геометрия, gates, хеши, ошибки
  frames/<video>/000000.png ...
  visible_masks/<video>/000000.png 000010.png ...
  masks/<video>/000000.png 000010.png ...
  review_initial/<video>.png
```

`visible_masks` — исходные видимые маски SAM; `masks` — геометрические маски для Cutie и оценки.
Оба типа одноканальные 0/1. Evidence включает четыре угла, поддержку сторон, охват,
отношение площадей и число добавленных пикселей. PNG допуска показывает первый кадр:
зелёное наложение полной маски, оранжевый четырёхугольник и синюю границу видимой маски.

Удаление PNG исключает всё видео, сохраняя кадры и обе маски. Возвращение файла с тем же именем
допускает видео в новых запусках. Повторная подготовка с прежними входами возвращает `EXISTING`,
не загружает SAM и ничего не восстанавливает. Для изменения входов или восстановления неполного
набора нужен новый output либо явный `--recreate`. Последний пересоздаёт только набор с подходящим
preparation marker. Исходные видео должны находиться вне output. Пути в manifest абсолютные.

## Обычный запуск Cutie

### Сравнительные видео сохранённых предсказаний Cutie

Просмотр запусков `phone-baseline-v5` и `phone-finetuned-v5`:

```bash
vlc results/phone-visual-comparison-v5/comparison.m3u
# Или открыть папку и выбрать отдельный MP4:
xdg-open results/phone-visual-comparison-v5
```

Каждый MP4 показывает три синхронные колонки: исходный кадр, оригинальная Cutie,
дообученная Cutie. Цветное наложение создаёт готовая функция `overlay_davis` из
официального checkout Cutie. Маски берутся из `predictions.jsonl`, исходные кадры
и временные метки — из `selected-manifest.jsonl`. Заданные начальные маски подписаны
отдельно. Инференс и загрузка весов не выполняются, звук в ролики не включается.

Повторная сборка в **новый** каталог из корня проекта:

```bash
uv run python scripts/render_cutie_comparison.py \
  --baseline results/phone-baseline-v5 \
  --finetuned results/phone-finetuned-v5 \
  --output results/phone-visual-comparison-v5-new
```

Нужны системные `ffmpeg` с `libx264` и `ffprobe`; дополнительных Python-пакетов
к текущему окружению проекта не требуется. По умолчанию высота изображения внутри
колонки ограничена 1080 пикселями: это уменьшенные визуализации, а не экспорт масок
или новая оценка качества. Для исходной высоты телефонных кадров используйте
`--panel-height 1920`. Маски масштабируются ближайшим соседом. Временные метки
сохраняются через VFR; длительность последнего кадра задаётся медианным интервалом.

Скрипт сверяет наборы кадров двух запусков, индексы, хеши и размеры предсказаний,
а после кодирования — число кадров и временные метки каждого MP4. `render.json`
содержит результаты проверки; рядом сохраняются JPG-превью и журналы FFmpeg.
`comparison.m3u` открывает все ролики по порядку в VLC.
Существующий output не перезаписывается. Для короткой проверки есть `--smoke`
(первые 12 кадров первого видео, также требует нового каталога).

### Инференс по подготовленной папке

```bash
uv run document-vos infer \
  --config configs/inference.yaml \
  --input-dir tools/phone_testset/data/my-test \
  --scope independent \
  --output results/own-baseline-v1
```

Обычному Cutie extra `phone-testset` не нужен. `--input-dir` заменяет YAML manifest и по умолчанию
выбирает independent, включая старый YAML с validation. Явный `--scope validation` при папке
запрещён; два явных `--input-dir` и `--manifest` запрещены. Явный `--manifest` сохраняет
обычный JSONL-режим и заменяет YAML-папку.

```yaml
input_dir: ../tools/phone_testset/data/my-test
scope: independent
```

YAML-пути относительны каталогу YAML; CLI-пути — текущему каталогу. YAML-папка без scope
получает independent, а заданный в этом YAML validation отклоняется.

До создания модели проверяются статус, PNG и маска кадра 0. Последующие маски не используются
для поиска другой инициализации непригодного видео. Счётчики выводятся в stderr; причины и
источники разметки сохранены в `selection.json`. Без пригодных видео — `NO_ELIGIBLE_VIDEOS`, без загрузки модели.

`selected-manifest.jsonl` в результате фиксирует входы оценки. Последующие удаления PNG и изменения
индекса влияют на новые запуски. Изменения самих кадров/геометрических масок обнаруживаются по хешам.
Baseline и finetuned требуют неизменного набора и состава допуска.

Cutie получает все кадры, геометрическую начальную маску — один раз. Первый кадр исключён из оценки;
при шаге 10 оцениваются кадры 10/20/30…, без интерполяции GT.
Это **согласие с автоматической геометрической псевдоразметкой без ручной проверки**,
а не качество относительно независимо проверенного полного контура. Ограничение обозначено в отчёте.

## Проверки

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 uv run --extra phone-testset --extra dev pytest -q \
  tests/test_phone_sam_geometry.py tests/test_phone_testset.py \
  tests/test_cli.py tests/test_inference_evaluation.py
```

Синтетические проверки покрывают перспективу, отверстия/закрытые углы/участки стороны,
отказы gates, обе маски, ошибки, шаги 10/7, PNG и явное пересоздание. Адаптер с тестовой
моделью проверяет offline-параметры, строгий checkpoint и bfloat16 confidence. Реальные
FFmpeg/ffprobe проверяют VFR/PTS/поворот; обычный infer с тестовым предиктором — отбор,
снимки и compatibility checks. Качество SAM и расход VRAM пока не измерены. Отдельный реальный
первоначальный smoke ограничен первыми кадрами девяти видео. Полная подготовка девяти
последовательностей после исправлений завершилась с NO_ELIGIBLE_VIDEOS и не является
оценкой качества относительно ручной разметки.
