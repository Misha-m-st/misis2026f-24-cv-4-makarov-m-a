# Повторное обучение и переносимые настройки

Параметры эксперимента находятся в `train-all.yaml`, корни данных — в
`all-datasets.yaml`, ресурсы исполнения — в `runtime-*.yaml`. Код не проверяет
модель GPU, объём RAM или конкретное число ядер. Веса и официальный checkout
должны уже находиться локально; эти команды ничего не скачивают.

## Профили исполнения

`runtime-cpu.yaml` — последовательная подготовка, отладка и CPU-инференс.
`runtime-cuda.yaml` — стартовый пример для CUDA. Официальный training launcher
поддерживает один CUDA-процесс; CPU training и multi-GPU training не заявляются.
`runtime-evaluation.yaml` задаёт отдельный CPU-бюджет метрик при GPU-инференсе.

Скопируйте профиль в `configs/my-machine.local.yaml` и измените лимиты.
Файлы `*.local.yaml` исключены из Git. Пути в YAML разрешаются относительно
самого YAML; CLI-пути — относительно текущего каталога.

```bash
uv sync --locked --extra dev
uv run --locked document-vos benchmark \
  --manifest data/prepared/manifest-v1.jsonl \
  --output artifacts/worker-benchmark-v1 \
  --runtime-config configs/runtime-cuda.yaml \
  --candidates 1 2 4 8 --frames 64
```

Benchmark обходит датасеты по очереди, использует одинаковые кадры для всех
кандидатов, проверяет совпадение результатов и сохраняет время, скорость и RSS,
если доступен. Замер включает запуск процессов и прогретый файловый кеш. Он не
измеряет холодный I/O и не заменяет benchmark DataLoader или метрик. Настройки
автоматически не применяются.

Секция `runtime` поддерживает `workers`, `io_threads`, `queue_size`,
`threads_per_worker`, `dataloader_workers`, `prefetch_factor`,
`persistent_workers`, `pin_memory`, `device`, `min_free_bytes`.
При нехватке ресурсов сначала уменьшайте workers/очереди, сохраняя параметры
эксперимента. Изменение batch size влияет на эксперимент и должно фиксироваться.

Приоритет: CLI → runtime-профиль → совместимые старые поля YAML → defaults.
Профиль может также находиться в секции `runtime` основного YAML.
`device: auto` разрешает CPU-инференс при отсутствии CUDA; явно запрошенная CUDA
требует доступную CUDA. `dataloader_workers: 0` отключает persistent workers и
prefetch. Для CPU-пулов последовательный режим — `workers: 1`.

## Нормализация локальных архивов

По умолчанию команда только показывает план:

```bash
uv run --locked document-vos prepare-archives \
  --config configs/prepare-archives.yaml \
  --runtime-config configs/my-machine.local.yaml
```

Добавьте `--execute`, чтобы начать. ZIP обрабатываются последовательно, кадры
внутри ZIP — процессами. TIFF превращаются в PNG без изменения декодированных
пикселей и разрешения; исходный TIFF-битстрим не сохраняется. Остальные файлы,
включая видео и GT, копируются без изменения байтов. MIDV-2019 получает внешний
каталог документа. TAR читаются независимыми читателями по offsets.

Проверяются опубликованные суммы/размеры архивов. Отсутствие авторской суммы Holo
явно отражается в квитанции. Для файлов сохраняются исходные и итоговые SHA-256,
для TIFF/PNG также проверяются пиксели. `.archive-receipt.json` публикуется только
после проверки полного состава. Повторная команда проверяет готовые результаты
и продолжает незавершённый архив по журналу. Конкурирующие записи блокируются.

Удаление выключено по умолчанию. Флаг `--delete-verified-zip` разрешает удалять
только ZIP после полной проверки, квитанции и синхронизации файлов. Этот флаг
не удаляет TAR. При ошибке архив сохраняется. Не запускайте downloader для
удалённых архивов повторно, если не хотите явно скачать их заново.

`min_free_bytes` задаёт резерв диска. Он проверяется при нормализации, экспорте,
перед обучением и записью предсказаний. Учитывайте полный объём архивов, видео,
PNG, JPEG training-экспорта, checkpoint и результатов. Незавершённые данные при
остановке сохраняются.

## Полный запуск

После нормализации исправьте корни в своей копии `all-datasets.yaml`, а пути
экспорта и результатов — в копии `train-all.yaml`. Старые версии сохраняйте.

```bash
# Только выбранные пути и настройки:
uv run --locked document-vos retrain --config configs/retrain.yaml \
  --runtime-config configs/my-machine.local.yaml

# Подготовка, проверки, smoke, 30 000 итераций и сравнения:
uv run --locked document-vos retrain --config configs/retrain.yaml \
  --runtime-config configs/my-machine.local.yaml --execute
```

Конвейер выполняет prepare/full-validation/split/export, проверяет наличие всех
выбранных датасетов в обеих частях и читает реальные примеры официальным loader.
Разбиение расширяет `split-v1`, сохраняя старые назначения. Новые связи между
старыми train и validation дают ошибку. DLC `.re` и телефонные custom-видео не
попадают в обучение.

В полном профиле DLC включён `skip_empty_via: true`: опубликованные VIA-проекты
без единой записи кадра исключаются из supervised-набора. Все исключённые клипы,
числа кадров, пути и хеши аннотаций записываются в `manifest-v2.meta.json`.
Исходники сохраняются. Непустая, но некорректная разметка продолжает давать ошибку.

Smoke-кандидаты задаются `smoke_workers`, длительность — `smoke_iterations`.
После каждого smoke веса действительно загружаются для короткого инференса.
Самый быстрый успешно проверенный кандидат выбирается по полному времени этапа,
включающему запуск и проверки. Любой сбой кандидата останавливает конвейер; он
не скрывается выбором другого кандидата. Основное обучение начинается заново
с базовых весов. Выбор workers не является поиском модели по качеству.

Статус и команды этапов: `results/retraining-v2/status.json`; логи — рядом.

Первая проверка training-экспорта читает хеши и маски полностью. Последующие
запуски используют SQLite-кеш только при совпадении ожидаемых хешей, версии
проверки, inode, размера, mtime и ctime обоих файлов. Это исключает повторное
декодирование неизменённых кадров при preflight/smoke/training. Для принудительной
полной проверки используйте `train --refresh-export`.
`dataset-counts.json` показывает видео и кадры каждой части. Основной training
сохраняет `training.log`, `resolved.yaml`, `plan.json`, `runtime.json` и
`result.json` в `results/training-v2`.

При повторе завершённые этапы пропускаются после проверки записанных хешей.
Изменение конфигурации запрещает продолжение в том же output. Изменение исходников
тоже требует нового output, кроме исправления orchestration/CLI в `cli.py` и
`retraining.py`: только явный `--resume-failed` разрешает повторить этап со статусом
`FAILED`, если все завершённые артефакты и логи на месте и их хеши совпадают.
Предыдущий лог сбоя сохраняется, повторный запуск получает отдельный лог
`<stage>.retry-N.log`. Этапы `RUNNING` автоматически не повторяются. Автоматический
resume оптимизатора не реализован.

После обучения оцениваются base/v1/v2 на новой и старой validation с одинаковым
внутренним размером 480. Для исторических весов дополнительно проверяются
исходный train, его provenance и отсутствие пересечения с новой validation.
Сравнение v1/v2 допускается при общем исходном checkpoint и совпадении парных
подписей. Один CPU-пул метрик совмещается с одним GPU-инференсом; настройки
обоих профилей должны соответствовать общему бюджету ресурсов.

Метрики считаются в исходном разрешении. Удаление общего нулевого фона сохраняет
пиксели, правила границ и радиусы от исходной диагонали; эквивалентность проверена
тестами. Первый кадр исключён, GT используется однократно, память сбрасывается
между видео. Прежние 296 просмотренных клипов после включения соответствующих
данных в обучение не являются независимым тестом. Телефонная оценка по
геометрическим псевдомаскам остаётся отдельной.

## Проверки

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 CUTIE_ROOT="$PWD/external/Cutie" \
  uv run --locked --extra dev pytest -q
uv run --locked --extra dev ruff check src scripts tests
uv run --locked --extra dev ruff format --check src scripts tests
uv lock --check
```

Реальная среда проверки — Linux. Windows/macOS и другие GPU не квалифицированы;
конкретная модель GPU не является условием в коде. Unit/CPU-тесты не доказывают
завершённое CUDA-обучение или прирост качества.
