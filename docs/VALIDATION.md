Команды воспроизведения в текущем окружении:

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 uv run --locked --extra dev pytest -q -m 'not official'
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 CUTIE_ROOT="$PWD/external/Cutie" uv run --locked --extra dev pytest -q -m official
uv run --locked --extra dev ruff check src scripts tests
uv run --locked --extra dev ruff format --check src scripts tests
uv lock --check
```

Чистый официальный checkout находится локально в ignored `external/Cutie`, ревизия `ec5cdd4cf16f75c73ad785a2f96fb97dbad4125a`. В первоначальной проверке 2026-10-09 в отдельном ignored `.venv-cutie` были установлены CPU PyTorch `2.14.1+cpu`, torchvision `0.29.1+cpu`, einops `0.8.2`, OpenCV-headless `4.14.0.94` и остальные зависимости Cutie. Тогда окружение проверяло loader/конструкторы/Hydra на CPU. Текущее единое CUDA-окружение описано ниже. Основные зависимости: Python `3.12.3`, NumPy `2.5.3`, Pillow `12.3.0`, SciPy `1.18.1`, matplotlib `3.11.2`, Hydra `1.3.2`, OmegaConf `2.3.1`. GPU-совместимость этих версий не заявляется на основании CPU-проверки.

Официальный Hydra-тест передаёт локальный placeholder-файл `weights`: проверяет путь и конфигурацию, не загружает его как модель. Тест state_dict создаёт случайную модель, проверяет все ключи и конверсию каналов, без настоящих pretrained weights. SpyPredictor в проверке распространения подтверждает контракт GT/reset/comparison; его идеальные синтетические маски и искусственный model time не являются измерениями Cutie.

При первом запуске на реальных данных сначала выполните `prepare`, проверьте междатасетные связи, затем экспорт. Отдельный `validate-data` после подготовки не нужен; полная проверка содержимого включается только через `--full`. Первый настоящий inference-run должен подтвердить полноту локального checkpoint и совместимость CUDA. Только после этого отдельным `train --execute` запускается дообучение. OOM сохраняется как ошибка, результаты незавершённого запуска не принимаются для сравнения.

## Устранение повторных проверок — 2026-10-10

Обычные команды используют структурный режим без хеширования кадров, декодирования пикселей и построения GT для проверки. Экспорт проверяет GT во время создания масок и не перечитывает готовый результат автоматически. Явный `validate-data --full` сохраняет покадровые результаты в SQLite; неизменившиеся кадры используют кеш. Изменение изображения, маски, координат или версии правил приводит к перепроверке, включая замену с сохранёнными размером и mtime. `--full --refresh` принудительно читает все кадры.

- Основной pytest: **50 passed, 3 deselected**. Добавлены 9 тестов отсутствия дорогих вызовов в обычных командах, повторного использования кеша между наборами/подмножествами, инвалидирования, обнаружения дублей по сохранённым хешам, продолжения после ошибки и CLI full/refresh.
- Ruff check, Ruff format и `uv lock --check`: PASS.
- Официальный Cutie на синтетическом экспорте: **2 passed** (VOSMergeTrainDataset и Hydra preflight). Загрузка настоящих весов и GPU не запускались.
- Реальный манифест `data/prepared/smartdoc-midv2020-v1.jsonl`: **1150 видео, 93 298 кадров, missing_gt=0**, структурная проверка заняла **8.84 с** (`/usr/bin/time`, один запуск). Это время проверки готового манифеста, не всей подготовки, экспорта или обучения.
- В этом запуске пиксели, пустота GT и побайтовые дубли **не проверялись**: `content_checked=false`, соответствующие счётчики `null`. Прирост качества, GPU и обучение этим изменением не измерялись.

## Настраиваемая параллельность — 2026-10-10

Добавлен общий CPU-пул с `workers=4` по умолчанию, стабильным порядком результатов и очередью не более `2×workers` задач. Параллельны экспорт кадров/масок, явная полная проверка некешированных кадров, проверка training-формата и оценка независимых видео. CLI поддерживает `--workers N`, YAML — верхнеуровневое `workers`; `workers=1` выполняет CPU-задачи в текущем процессе. При обучении этот параметр задаёт официальный `num_workers` загрузчика, сохраняя одну GPU-модель. SQLite остаётся в родительском процессе. В CLI добавлен прогресс/скорость/ETA в stderr.

- Основной pytest: **61 passed, 3 deselected**. Проверены запуск четырёх разных рабочих процессов, последовательный режим, граница очереди, ошибки параметра, побайтовое совпадение экспорта, совпадение всех метрик/агрегатов, кеш и ошибки рабочих процессов без записи COMPLETE-экспорта.
- Официальный VOSMergeTrainDataset и Hydra preflight: **2 passed** на синтетическом экспорте. Новое число загрузчиков проверено конфигурацией, GPU-обучение не запускалось.
- Ruff check, Ruff format, `uv lock --check`: PASS.
- Малый замер **128 реальных кадров MIDV-2020**: workers=1 — **4.150 с / 30.8 кадров/с**, workers=4 — **1.515 с / 84.5 кадров/с**, ускорение **2.74×**. Имена, порядок и хеши результатов совпали. Запуск процессов включён в время; старый пользовательский экспорт одновременно продолжал работать. Временные экспортные файлы удалены; исходные данные и текущий экспорт сохранены. [Результат замера](../data/benchmarks/parallel-export-smoke-20261010.json).

Это замер небольшого фрагмента CPU-экспорта; полное время экспорта, скорость Cutie, GPU-память и качество этим замером не подтверждены. Инференс внутри видео остаётся последовательным из-за памяти VOS; лёгкая подготовка и разбиение не запускают CPU-пул. Уже запущенный экспорт продолжает исполнять старый код.
