# Cutie для видео документов

[Повторное обучение на шести датасетах и переносимые профили исполнения](RETRAINING.md).

Python-проект `document_vos`: подготовка → безопасное разбиение → baseline → официальное дообучение → finetuned → парное сравнение. Документация и команды запуска находятся здесь; исходный пользовательский `main_plan.md` сохраняется.

## Установка и устройство

Нужны Python 3.12, `uv` и NVIDIA GPU с драйвером, совместимым с CUDA 13.0. Все зависимости Cutie, включая CUDA PyTorch, устанавливаются в обычное окружение `.venv`:

```bash
uv sync
uv run document-vos --help
uv run python -c 'import torch; print(torch.__version__, torch.version.cuda, torch.cuda.is_available(), torch.cuda.get_device_name(0))'
```

`pyproject.toml` закрепляет PyTorch 2.14.1 и torchvision 0.29.1 за официальным индексом CUDA 13.0 на Linux/Windows, а `uv.lock` фиксирует полное окружение. Эта пара проверена на RTX 4060 Laptop с драйвером 580.178.04. Обычный `uv run document-vos …` использует подготовленную CUDA-сборку. Загрузка Python-зависимостей не скачивает датасеты или контрольные точки.

Для проверок установите extra `dev`:

```bash
uv sync --extra dev
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 uv run --extra dev pytest -q -m 'not official'
```

`PYTEST_DISABLE_PLUGIN_AUTOLOAD=1` защищает проверки от чужих pytest-плагинов, например ROS. Python-пакет Cutie не устанавливается из плавающей ветки: используем его чистый локальный checkout.

```bash
git clone https://github.com/hkchengrex/Cutie.git external/Cutie
git -C external/Cutie checkout ec5cdd4cf16f75c73ad785a2f96fb97dbad4125a
```

Исходники интегрированы по [официальному training pipeline](https://github.com/hkchengrex/Cutie/blob/ec5cdd4cf16f75c73ad785a2f96fb97dbad4125a/docs/TRAINING.md). Код архитектуры и forward не меняется. Cutie вызывает загрузку ImageNet при создании ResNet: наш launcher отключает только эту инициализацию, загружает **полный локальный checkpoint** и проверяет все ключи/размеры. В pinned upstream при переходе multi-object → single-object loader обрезает other-object канал `mask_encoder.conv1`, но пропускает соответствующий канал `pixel_fuser.sensory_compress`. Адаптер дополняет эту конверсию обрезанием последнего входного канала fuser; при единственном документе этот вход равен нулю. При инференсе используется общая multi-object архитектура с объектом `1`; при загрузке single-object весов дополнительные каналы заполняются нулями официальным loader. Обе конверсии проверяются на CPU. Неполные веса завершают запуск ошибкой, случайно инициализированные отсутствующие параметры не допускаются.

Основные модули:

| Модуль | Назначение |
|---|---|
| `adapters`, `data` | Чтение источников, JSONL, GT и проверки |
| `geometry`, `split`, `export` | Пересечение с кадром, компоненты связей, training-format |
| `cutie`, `training`, `training_worker`, `inference` | Официальный Cutie, Hydra, torchrun, перенос маски |
| `metrics`, `evaluation`, `comparison`, `reports` | Метрики, парные результаты, CSV/JSON/PNG/Markdown |

## Параллельная обработка CPU

В `export-training`, `validate-data --full`, `evaluate` и `train` есть один параметр **`--workers N`**, по умолчанию **4**. Это число независимых рабочих процессов; операционная система распределяет их между ядрами. Привязывать процессы к конкретным ядрам не нужно. Для CPU-операций `--workers 1` выполняет задачи последовательно в текущем процессе. Значения меньше 1 не допускаются. В YAML можно задать верхнеуровневое `workers: 4`; явный CLI-аргумент имеет приоритет.

- Экспорт и проверка training-формата распределяют кадры между процессами.
- Полная проверка распределяет только кадры, которым нужна перепроверка; кеш ведёт родительский процесс.
- Оценка метрик распределяет независимые видео, сохраняя порядок кадров, соседние изменения и усреднение.
- При обучении `workers` задаёт официальный `num_workers` загрузчика данных и сохраняется в resolved-конфигурации. GPU-модель остаётся одна. Изменение числа загрузчиков может менять случайные аугментации; фиксируйте его для воспроизводимого обучения.

Например:

```bash
uv run --locked document-vos export-training --manifest data/split-v1/train.jsonl --split-dir data/split-v1 --output data/training-v1 --workers 4
uv run --locked document-vos validate-data --manifest data/prepared/manifest-v1.jsonl --full --workers 8
uv run --locked document-vos evaluate --run results/baseline-v1 --output results/baseline-eval-v1 --workers 4
```

Экспорт, полная проверка, проверка training-формата и оценка показывают прогресс, скорость и примерное оставшееся время в stderr; JSON-результат остаётся в stdout. Очередь задач ограничена, между процессами передаются пути и координаты вместо полноразмерных изображений. Файлы масок, порядок кадров и значения метрик одинаковы в последовательном и параллельном режимах. Число процессов не задаёт жёсткую привязку к ядрам; увеличение workers ограничивается доступной памятью и скоростью диска.

Подготовка/разбиение выполняют лёгкие структурные операции. Инференс кадров одного видео остаётся последовательным: следующий кадр использует память предыдущих. Уже запущенный процесс не переключается на новый код или другое число workers; существующий экспорт не перезаписывается новым запуском.

## Скачивание и подготовка

[Каталог скачивания](DATASETS.md) содержит команды, размеры, контрольные суммы и необходимые архивы для всех восьми наборов. Ни одна CLI-команда не скачивает данные или веса. Старт: SmartDoc 2015 + MIDV-2020, **11.323 ГБ архивов**. Запас диска **40–60 ГБ** — предварительная оценка, а не измеренное требование; перекодированный экспорт может увеличить расход.

Распакуйте наборы вне Git, исправьте `configs/starter.yaml`. YAML-пути относительны файлу конфигурации; пути CLI относительны текущему каталогу. Можно выбрать любой непустой список из `smartdoc2015`, `midv500`, `midv2019`, `midv2020`, `midvlait`, `midvholo`, `dlc2021`, `sidtd`. Не выбранные наборы не читаются и могут отсутствовать.

Стартовый профиль можно скачать скриптом: `python3 scripts/download_datasets.py`. Только MIDV-2020: `python3 scripts/download_datasets.py --datasets midv2020`. Он определяет пути от корня проекта, докачивает после обрыва, проверяет суммы и распаковывает. `--plan` показывает план без сети; остальные команды pipeline сами загрузку не запускают. Подробнее в [каталоге скачивания](DATASETS.md).

```bash
uv run document-vos prepare --config configs/starter.yaml
uv run document-vos split --manifest data/prepared/manifest-v1.jsonl --output data/split-v1 --seed 42 --val-fraction 0.2
uv run document-vos export-training --manifest data/split-v1/train.jsonl --split-dir data/split-v1 --output data/training-v1
```

Обычные `prepare`, `split`, `validate-data` и проверка входа `export-training` читают только структуру и разметку: наличие файлов, уникальность путей/ID, геометрию четырёхугольников, время и происхождение. Они **не хешируют кадры, не декодируют изображения и не строят маски для проверки**. Отдельный `validate-data` после `prepare` не нужен. Целостность скачанного архива проверяет downloader.

Проверка содержимого доступна отдельно, если она понадобится:

```bash
uv run document-vos validate-data --manifest data/prepared/manifest-v1.jsonl --full
# Принудительно перечитать все кадры, игнорируя прежний результат:
uv run document-vos validate-data --manifest data/prepared/manifest-v1.jsonl --full --refresh
```

`--full` вычисляет хеши для поиска побайтовых дублей, декодирует изображения, проверяет размеры/метки GT и наличие непустой начальной маски. Результаты сохраняются в `.validation-cache.sqlite3` рядом с манифестом. Неизменившиеся кадры повторно не читаются: учитываются путь, устройство/inode, размер, mtime/ctime, файл маски, координаты разметки и версия правил. Кеш применим к другим версиям и подмножествам манифеста; общий путь можно задать через `--cache data/.validation-cache.sqlite3`. При изменении файла или разметки проверяется только изменившийся кадр. Для принудительной сверки содержимого используйте `--full --refresh`.

В структурном режиме `validation=structural`, `content_checked=false`, а `empty_gt` и `repeated_frames_within_video` равны `null`: эти свойства не измерялись. Это не означает ноль пустых масок или побайтовых дублей. Полный режим показывает число заново проверенных `checked_frames` и использованных из кеша `cached_frames`. Экспорт создаёт необходимые обучению маски и проверяет их при построении; повторного полного чтения только что созданного экспорта нет. Перед обучением отдельная проверка training-формата остаётся. Инференс читает кадры для модели и сохраняет хеши для воспроизводимого сравнения, без предварительного декодирования всей выборки.

Одна JSONL-строка содержит **всё видео**: `schema_version`, `dataset`, `video`, `document`, `template`, `group`, `frames`, `time_source`, `provenance`. Кадр содержит `id`, `path`, `time_s` и один из `polygon`/`mask`; оба отсутствуют, если GT нет. Маска — одноканальная PNG с метками `{0,1}`; пустая маска является GT, а отсутствие GT — отдельный случай. Пути в подготовленном манифесте абсолютные. Порядок кадров сохраняется, GT не интерполируется. [Пример явного индекса](../examples/sequences.jsonl) нужен для SIDTD, собственных видео и нестандартных раскладок остальных наборов. Этот пример описывает формат, изображения к нему не прилагаются.

Нативные адаптеры читают SmartDoc `metadata.csv.gz`, MIDV-500/2019/LAIT/Holo `quad` JSON и MIDV-2020/DLC VIA 2 JSON. Неверный или неоднозначный формат не исправляется догадками. Если конкретный релиз отличается, используйте индекс `sequences.jsonl` и параметр `index` в секции датасета. В индексе можно задать явные `frames` или `images` вместе с `annotation` (VIA) либо `ground_truth` (каталог quad JSON).

SmartDoc имеет переменную частоту кадров, а CSV не содержит timestamps. Поэтому по умолчанию `time_s=null`. При известных исходных timestamps задайте их в индексе. `fps` допустим только как явная настройка вместе с `time_source`; он вычисляет время из исходного числового суффикса кадра и учитывает пропуски. Без временных меток график использует нормализованный индекс кадра и явно сообщает это.

Геометрия: четыре конечные точки выпуклого невырожденного контура по обходу; пересечение с изображением выполняется до растеризации, вместо зажимания углов. Координаты соответствуют центрам пикселей `[0,w−1] × [0,h−1]`, заполнение выполняется Pillow. Нулевой результат при выходе документа из кадра допустим. Четырёхугольник может включать перекрывающую руку; он не описывает точный контур изогнутой страницы. Поэтому эти маски измеряют совпадение **аннотированной области документа**, а не видимой поверхности или физической геометрии страницы.

В DLC принимаются `or`, `cc`, `cg`; `re` отбрасывается. В SIDTD нужен явный индекс с `presentation=physical`, `origin`, `source_dataset`, `annotation_source` и проверенными идентификаторами связей. Экранные видео и источники MIDV-2020 исключаются. Если новая SIDTD видео-часть не имеет подтверждённой локализации/происхождения, её нельзя включать в выбранный профиль: preparation завершится ошибкой. Поддержка адаптера не означает наличие GT у любого опубликованного варианта SIDTD.

## Связи и версии разбиения

Связи задаются **глобальными**, согласованными идентификаторами. Для MIDV-500/2019 общие документы получают одинаковый family ID; шаблоны известных MIDV типов имеют общий `midv-template:<code>`. MIDV-2020/DLC экземпляры связываются по типу и номеру. Проверяйте эти соответствия для своих релизов. MIDV-LAIT/Holo имеют собственные пространства идентификаторов; дополнительные связи с другими наборами задаются вручную.

Неизвестные связи задайте таблицей JSON вида `{"dataset/video": {"document": "global-id", "template": "global-template", "group": "global-related-group"}}`, укажите `relationships` в prepare-конфигурации. [Пример](../examples/relationships.json) демонстрирует синтаксис и не заменяет аудит реальных соответствий. Один и тот же экземпляр, исходный шаблон и физические копии должны иметь общие связи даже между наборами.

Split объединяет транзитивно совпадающие `document`, `template`, `group`; компонента целиком принадлежит одной части. Seed 42, приблизительно 80/20 по видео. Из-за размеров компонент точные 80/20 и покрытие каждого датасета в обеих частях не гарантируются: фактическая доля и группы записываются в `split.json`. Менее двух компонент — ошибка. В явном `validate-data --full` побайтовые повторы кадров между видео запрещены, а внутри видео учитываются диагностикой. Обычный split проверяет пересечения идентификаторов и путей, без поиска побайтовых дублей. Хеши не находят визуально похожие кадры после перекодирования, поэтому таблица связей остаётся обязательной для неизвестных связей.

При расширении сохраняйте прошлые файлы:

```bash
uv run document-vos prepare --config configs/starter.yaml --datasets smartdoc2015 midv2020 midv2019 midvholo --output data/prepared/manifest-v2.jsonl
uv run document-vos split --manifest data/prepared/manifest-v2.jsonl --previous data/split-v1 --output data/split-v2
```

Старые видео и назначения сохраняются. Новая связь между прежними train и validation — ошибка: потребуется отдельный эксперимент с новой версией, а не скрытое перемещение видео. Существующие файлы результатов не перезаписываются. Подготовка выполняет только структурную проверку; размеры и бинарные значения GT проверяются при их чтении для экспорта или инференса либо отдельно в `validate-data --full`.

## Экспорт и обучение

Экспорт создаёт отдельные `images/video_id/000000.jpg` и `masks/video_id/000000.png`. Только кадры с GT; размер маски совпадает с изображением, значения 0/1, порядок и исходные имена/время сохранены в `export.json`. Совместимые RGB JPEG и бинарные PNG подключаются ссылками; остальные кадры перекодируются в отдельный каталог. `--copy` отключает ссылки. Оригиналы не изменяются. Видео короче `seq_length` после удаления кадров без GT записываются в `skipped_short`; отсутствие пригодных видео — ошибка. Изменение исходников, на которые ведут ссылки, обнаруживается проверкой хешей.

Профиль по умолчанию для 8 ГБ: batch 2, sequence 8, crop 480×480, 3 reference frames, AMP, LR 1e−5, 10000 итераций. На RTX 4060 Laptop короткий замер официального Trainer с этими размерами прошёл; длительный запуск ещё не проверен. Модель загружается только из явно указанного локального `weights`. Начальные network weights `cutie-base-mega.pth` доступны в [официальном релизе v1.0](https://github.com/hkchengrex/Cutie/releases/tag/v1.0). Команды из корня проекта:

```bash
mkdir -p weights
curl --fail --location --retry 3 \
  --output weights/cutie-base-mega.pth.part \
  https://github.com/hkchengrex/Cutie/releases/download/v1.0/cutie-base-mega.pth
printf 'a6071de6136982e396851903ab4c083a  weights/cutie-base-mega.pth.part\n' | md5sum --check && \
  mv weights/cutie-base-mega.pth.part weights/cutie-base-mega.pth
sha256sum weights/cutie-base-mega.pth
```

MD5 указан в `cutie/utils/download_models.py` зафиксированного upstream; окончательное имя появляется только после совпадения суммы. Не используйте checkpoint-state с optimizer вместо network weights.

```bash
# Сначала только план, официальная Hydra-композиция и --cfg job --resolve, без обучения:
uv run document-vos train --config configs/train-8gb.yaml --output results/training-plan-v1
# Длительный GPU-запуск только при явном --execute, в новом каталоге:
uv run document-vos train --config configs/train-8gb.yaml --output results/training-v1 --execute
```

Guards: `pre_training.enabled=false`, `main_training.enabled=true`, `num_objects=1`, `merge_probability=0.0`. В `data` только DOCUMENTS из проверенного train-экспорта; стандартные DAVIS/YouTubeVOS/static наборы исключены. Переопределять guards нельзя. Сохраняются resolved YAML, доказательство Hydra-разрешения, seed, хеши checkpoint/манифеста/split/экспорта, версии, журналы и training-result. Запуск — официальный `cutie/train.py` через single-GPU `torchrun`, без изменения его цикла. OOM завершает запуск со статусом ошибки; batch/crop/guards автоматически не ослабляются. Peak allocated/reserved записываются в `runtime.json` при выполнении worker.

Проверка training-экспорта выводит только начало и итог. Во время обучения
в терминале обновляется одна строка: итерации, процент, elapsed/ETA, скорость,
усреднённый train loss и learning rate. Метрики поступают каждые 25 итераций;
полный журнал, предупреждения и traceback сохраняются в `training.log`.
При ошибке прогресс не доводится до 100%. Изменения вывода действуют для новых запусков.

Перед длительным обучением можно запустить [короткий замер вместимости](CAPACITY.md):
официальные 480×480 / 8 кадров / batch 16, снижение только после CUDA OOM,
до первого успешного варианта. Это отдельный smoke-замер, который не сохраняет
дообученные веса и не заменяет оценку качества.

## Baseline, finetuned и отчёт

```bash
uv run document-vos infer --config configs/inference.yaml --output results/baseline-v1
uv run document-vos evaluate --run results/baseline-v1 --output results/baseline-eval-v1

uv run document-vos infer --config configs/inference.yaml --weights results/training-v1/official/documents_main_training_last.pth --training-run results/training-v1 --output results/finetuned-v1
uv run document-vos evaluate --run results/finetuned-v1 --output results/finetuned-eval-v1
uv run document-vos compare --baseline results/baseline-eval-v1/evaluation.json --finetuned results/finetuned-eval-v1/evaluation.json --output results/comparison-v1
uv run document-vos report --source results/comparison-v1/comparison.json --output results/report-v1
```

Для каждого видео выбирается первая размеченная непустая GT; более ранние кадры пропускаются. После неё обрабатываются **все** кадры, включая кадры без GT. GT далее модели не передаётся. Для каждого видео создаётся новый InferenceCore, включая новый object manager. Первую GT исключаем из метрик; последующие пустые GT оцениваем. Пропуски GT считаем отдельно. Отсутствующее предсказание — ошибка даже на кадре без GT. Результаты сохраняются в исходном разрешении, resizing масок перед оценкой не выполняется.

Веса baseline и finetuned могут различаться; их входы, первые маски, память, seed, device, версии библиотек, revision и inference config должны совпадать. Сравнение проверяет хеши данных и полноту набора оценённых кадров. `--training-run` подтверждает происхождение finetuned от checkpoint baseline и принадлежность тому же разбиению; произвольные внешние веса не выдаются за результат нашего дообучения.

### Метрики и временные показатели

- J = IoU областей; F использует границу и евклидов допуск DAVIS `ceil(0.008 × диагональ)`; J&F = (J+F)/2.
- BIoU использует внутреннюю полосу `max(1, round(0.02 × диагональ))`; 3×3 erosion с нулевым дополнением учитывает края изображения.
- Обе пустые маски: все четыре метрики 1; одна пустая: 0. Отдельно выводится качество на непустой GT.
- Основное среднее: кадры → равные видео внутри датасета → равные выбранные датасеты. Дополнительно: все видео поровну и все кадры. Видео без оценённой GT перечисляются отдельно; датасет без оценённых кадров делает оценку невозможной.
- Decay J/F/BIoU: разница первой и последней из четырёх перекрывающихся групп DAVIS; индексы int64 безопасны для длинных видео. Один оценённый кадр даёт decay 0; пустая последовательность NOT_MEASURED.
- CSV хранит BIoU каждого видео по кадрам/времени, std J&F (population std, ddof=0), signed/absolute соседние изменения. Соседство проверяется по исходным индексам: пропуск GT не превращает несоседние кадры в соседние.
- Общая BIoU-кривая: 10 интервалов длительности от инициализации до последнего кадра с той же основной политикой усреднения. Показывается число видео и распределение датасетов в каждом интервале; нет наблюдений — пропуск, без заполнения нулями.
- Сравнение сохраняет парные изменения finetuned − baseline по кадрам/видео, включая изменение decay и std. Падение по времени само по себе не доказывает накопление ошибки: для этого нужен отдельный контрольный эксперимент.

Метрики соответствуют [официальному DAVIS evaluator](https://github.com/davisvideochallenge/davis2017-evaluation) и [Boundary IoU](https://github.com/bowenc0221/boundary-iou-api) с оговорённой политикой пустых масок. Это отдельная document-оценка, не официальная оценка оригинальных соревнований SmartDoc/MIDV.

FPS модели измеряет InferenceCore.step после подготовки tensor, с синхронизацией CUDA вокруг вызова; полный FPS включает чтение, преобразование, передачу, инференс и запись PNG. Инициализация включена, отдельного warmup нет. Загрузка checkpoint и подготовительная проверка хешей не входят в FPS. Peak allocated/reserved — измеренные счётчики CUDA, CPU даёт NOT_MEASURED. Результат подмножества всегда подписывается как результат этого подмножества.

### Собственные независимые видео

Запишите новые документы; извлеките кадры и задайте реальные timestamps и ручную GT в явном индексе. Не подключайте их к train/split. Например, YAML:

```yaml
selected: [custom]
datasets:
  custom:
    root: ../data/independent
    index: sequences.jsonl
```

```bash
uv run document-vos prepare --config configs/custom.local.yaml --output data/independent-v1.jsonl
uv run document-vos infer --config configs/inference.yaml --manifest data/independent-v1.jsonl --scope independent --output results/own-baseline-v1
uv run document-vos evaluate --run results/own-baseline-v1 --output results/own-baseline-eval-v1
```

Повторите с finetuned и `--training-run`, затем сравните эти два independent-run отдельно. Смешивание scope или включение custom в validation не допускается.

## Проверки и пределы результатов

Набор pytest покрывает геометрию, края/пустые/смещённые маски, усреднение на неравных длинах/датасетах, короткий/длинный decay, фильтрацию DLC/SIDTD, опубликованные малые CSV/JSON-схемы всех восьми наборов, воспроизводимость и отсутствие пересечений split, расширение split, экспорт, guards обучения, GT только один раз, reset памяти, missing predictions и несовместимые сравнения.

Проверки официальной интеграции, без загрузки настоящих весов и без GPU:

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 CUTIE_ROOT="$PWD/external/Cutie" uv run --extra dev pytest -q -m official
```

Они загружают **синтетический** экспорт официальным VOSMergeTrainDataset, проверяют создание CUTIE без сети/отклонение неполного state_dict и реальное Hydra-разрешение training config. Dummy-файл в Hydra-тесте проверяет только конфигурацию, не валидность настоящего checkpoint. Формат реальных архивов, качество baseline/finetuned, 8 ГБ VRAM, GPU throughput и завершённое обучение требуют отдельных явных запусков. [Текущий протокол проверки](VALIDATION.md).

Данные, веса, результаты и внешние исходники исключены из Git. Пользовательские изменения не коммитятся автоматически.

## Телефонный независимый test set

[Подготовщик SAM 3 + геометрия листа](../tools/phone_testset/README.md) размечает первый и каждый
десятый кадр в общем uv-окружении. Видимые маски сохраняются отдельно; Cutie и оценка используют
геометрическую гипотезу полного контура плоского листа. Импорт SAM 3 Image проверен;
реальный smoke с локальными весами/телефонным видео — NOT_RUN.
Обычный `infer` принимает `--input-dir`/YAML `input_dir`, отбирает последовательности по
`review_initial/*.png` и начальной маске, сохраняет выбранный JSONL и не загружает модель при пустом отборе.
Оценка по таким маскам обозначается как автоматическая геометрическая псевдоразметка без ручной проверки.
